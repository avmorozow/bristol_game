# Бристоль — Собери пакет

[Открыть игру без регистрации](https://bristol-soberi-paket.meowed.chatgpt.site)

Рабочая демонстрация мобильной игры по БФТ, таблице баланса и макетам Figma. Входит: обучение, 120 тапов, случайная белка, один бустер, фиксация выигрыша, ежедневная бесплатная попытка, платные попытки, приглашение друга, история операций, тестовый подарок и демонстрационные сценарии.

## Запуск и проверка

- `npm run install:ci` — установить зависимости.
- `npm run dev` — локальная разработка с эмуляцией Cloudflare.
- `npm run build` — собрать сервер и клиент.
- `npm test` — сборка и автоматические проверки.
- `node --test tests/game.test.mjs` — игровые сценарии и API с настоящей SQLite через адаптер D1.
- `npx tsc --noEmit --incremental false` — проверка типов.
- `npm run db:generate` — сгенерировать миграцию после изменения `db/schema.ts`.

Игра открывается без регистрации и входа через ChatGPT. Сервер автоматически выдаёт гостевую cookie (`HttpOnly`, `SameSite=Lax`, `Secure` на HTTPS, срок 1 год). В базе хранится хеш случайного 256-битного токена. Баланс и подарки восстанавливаются в том же браузере; другой браузер или удаление cookie создают новый гостевой профиль. Старые приватные профили не становятся общедоступными.

Для локальной разработки один раз выполните `npm run db:local`, чтобы применить начальную миграцию к эмулятору D1. Команда предназначена для пустой локальной базы; production D1 управляется Sites.

## Архитектура

`app/game.tsx` — адаптивный интерфейс и управление командами. `lib/game/tap-queue.ts` — очередь быстрых нажатий с немедленной анимацией и объединением ожидающих тапов (до 20) в запрос. Сервер проигрывает каждый тап по очереди и прекращает серию на первой белке или финале. «Забрать» ждёт обработки уже принятых нажатий; новые после этого не принимаются. Неотправленные нажатия отменяются при выходе или потере связи. `lib/game/engine.ts` — чистая машина состояний. `lib/game/economy.json` — точные 120 строк листа «Новый баланс». `app/api/game/route.ts` — гостевые сессии, RNG, идемпотентные команды и оптимистическая блокировка. `db/schema.ts` и `drizzle/` — игроки, команды, события и миграции.

Авторитетное состояние и тестовый кошелёк хранятся в D1. Клиент не определяет выигрыш и не списывает монеты. Изменение игрока, результат команды и событие записываются одной транзакцией D1 batch. Начисление реферального бонуса обеим сторонам также атомарно. Повтор игровой команды возвращает сохранённый ответ, не вызывает новый RNG и не повторяет платёж. Heartbeat продлевает время активности одним запросом, не меняет игровую ревизию и не блокирует нажатия. При конфликте версий клиент обновляет состояние. Локально хранятся только настройка звука и неподтверждённая команда; игровой баланс не хранится в localStorage.

Потенциальный выигрыш — общая сумма из таблицы для текущего тапа, а не сумма всех строк. Платная попытка списывает 100 монет отдельно; её первый успешный тап даёт 102. Бустер восстанавливает тот же неудачный тап без повторного розыгрыша. Вторая белка после бустера завершает игру с нулевым выигрышем.

При переключении вкладки или перезагрузке попытка сохраняется. Можно вернуться в течение 5 минут после последней активности. Затем при следующем запросе сервер фиксирует последний подтверждённый выигрыш; `loss_pending` заканчивается без награды. Явная кнопка выхода завершает конкретную попытку сразу. Отдельного фонового планировщика в демо нет. Подарок создаётся ровно один раз при фиксации 120-го тапа. Закрытие результата сохраняется на сервере.

Под выигрышем показаны сумма следующего удачного тапа и вероятность белки из исходной таблицы. Бустер не обещает выгоду: когда цена спасения не меньше награды, интерфейс объясняет это. Итог попытки показывает потраченные монеты и чистое изменение баланса. Неподтверждённые нажатия отображаются сразу; запросы имеют 12-секундный тайм-аут и повторяются с тем же ключом операции.

## Демо-профиль

- Профиль `new_balance_120_draft_v1`, 120 тапов из предоставленного Excel.
- Начальный баланс: 1 000 тестовых монет.
- Бесплатная попытка обновляется в 00:00 UTC; дополнительные стоят 100.
- Бустер: 50 монет, один раз за попытку.
- Финал: 2 350 в бесплатной / 5 000 в платной попытке.
- Код друга активируется до первой игры. Бонус — 100 каждой стороне. Лимит пригласившего — 5 в сутки / 20 всего.
- `BRISTOL` — демонстрационный код, доступный каждому гостю один раз до первой обычной игры. Он не исчерпывает общий лимит на всех посетителей. Для настоящих приглашений сохраняются лимиты 5/20.
- Кнопка «Демо · тестовые монеты» открывает пополнение и отдельные сценарии: финал на следующем тапе, белка на 4-м и 8-м тапах. Эти сценарии явно помечены и не меняют вероятности обычной игры.
- Подарок — демонстрационный код, не действующий при покупках.

## Источники и ограничения

Оригинальные изображения экспортированы из предоставленного Figma-файла: https://www.figma.com/design/8X1QVowocbd3gO7KSufe5I/ — узлы 720:5524, 720:5577, 726:4130, 720:5954, 740:5881 и вложенные компоненты. Используются собственные простые звуковые сигналы Web Audio; в исходниках аудиофайлов не было.

Это демонстрация, а не интеграция с боевой программой лояльности. Реальные Bristol SSO, баланс, транзакции, каталог/выдача промокодов и внешняя аналитика не подключены. Монеты и подарки подписаны как тестовые во всех соответствующих потоках. Розыгрыш билетов не входит в эту версию. Бустер 50, профиль 120 тапов и реферальные лимиты — рабочие допущения из инструкции, требующие утверждения для боевого запуска.

Для интеграции необходимо получить подтверждённые endpoint, авторизацию, ключи и ответы API по контракту; заменить тестовый кошелёк адаптером лояльности и выдачу подарков реальным поставщиком; добавить outbox, reconciliation и фоновые задачи; согласовать возвращение в приложение, таймзону, тариф бустера, лимиты и состав аналитики. Не переключать демо на реальные списания одной настройкой.

## Проверенные сценарии

Проверки движка и API покрывают таблицу выплат, сброс бесплатной попытки, бустер без повторного RNG, вторую белку, выдачу финального подарка, фиксацию после обрыва связи, изоляцию гостевых профилей, отсутствие обязательного входа, cookie, запрет запросов с чужого сайта, конкурирующие запуски, повторные команды и выплаты, запоздалое закрытие старой попытки, атомарные рефералы, собственный/повторный код и лимиты.

Подробности игрового и визуального прогона: [docs/playtest-report.md](docs/playtest-report.md).

## Размещение

Для игры нужны Worker и база D1. GitHub Pages сам по себе эту серверную версию не запускает. Для повторной публикации через Sites выберите новый проект и сохраните его ID локально в `.openai/hosting.json`; в репозитории ID проекта не хранится.
